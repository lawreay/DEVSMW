# UI Guidelines

## Product Feel

The app should feel clean, useful, and trustworthy. It is a directory and admin tool, not a marketing landing page.

## Public UI

* First screen should show search immediately.
* Profile cards should show name, username, rank, location, work, and a short summary.
* Search should cover name, username, work, location, bio, and strengths.
* Profile pages should separate contact details, source links, projects, and skill summaries.
* Missing data should say `Not publicly available`.

## Admin UI

* Admin dashboard should prioritize quick scanning.
* Each row should have Edit and Refresh GitHub actions.
* Edit forms should keep data fields obvious.
* Admins should see visibility and consent/review status.
* Risky profiles should be set to `draft` or `hidden`.

## Tone

Use factual, respectful language. Avoid exaggerated claims. For inferred skills, use phrases like "Likely focus areas" or "Public repository languages" rather than claiming certainty.

## Accessibility

* Use readable contrast.
* Keep buttons and inputs large enough for mobile.
* Use real text instead of images for profile information.
* Ensure pages work without JavaScript.
